# 侧边会话 / Session Panel

中文 | [English](README.en.md)

`@dsh-local/session-panel` · `2.4.0-dsh020rc2.9` · 适配 DSH Desktop `0.2.0-rc.2`

给每个主对话配一个独立、可持续保存的侧边 Agent：主任务照常执行，你可以在右侧问“当前做到哪一步”“这个术语是什么意思”，也可以让侧 Agent 独立处理获准任务。

这是社区插件，不是 DeepSeek 官方插件。插件内的 JavaScript 是可直接维护的源码，不需要额外编译；插件提示语目前以中文为主。

## 能做什么

- 复用官方聊天组件：流式回复、Markdown、思考与工具展示、图片/附件、`+`、`@`、`/`、模型和权限选择、发送/排队/停止。
- 每个主对话对应独立侧会话，历史和草稿不串用；关闭再打开、滚动与调整宽度使用官方右栏布局。
- `side_main_read` 只读查询所属主对话的状态、消息、轨迹和事件；支持搜索、固定快照分页及长事件分段读取。
- 停止侧任务不停止主任务，停止主任务也不停止侧任务。没有“发送到主对话”按钮或投递接口。
- 历史订阅断线后重连，由官方状态机补读、去重；持续失败显示提示及“重新连接”。只重连读取通道，不重发问题。

“复用官方组件”不意味着已经穷尽验证所有第三方工具或未来官方功能。

## 安装、升级与卸载

### 方式一：直接粘贴安装包地址（推荐）

确认 DSH Desktop 为 `0.2.0-rc.2`，打开左侧「插件 → 添加插件」。将下面整行粘贴到「包名或地址」输入框：

```text
https://github.com/hechucaixuanzhi/my-dsh-plugins/releases/download/session-panel-v2.4.0-dsh020rc2.9/dsh-local-session-panel-2.4.0-dsh020rc2.9.tgz
```

1. 「安装源」保持默认、npm 官方源或中国大陆镜像源即可；它选择 npm 下载源，下载依赖时仍可能使用。**不要把上面的地址填进“安装源 / 自定义地址”。**
2. 点击「安装」，等待完成，在已安装列表中确认 `@dsh-local/session-panel` 已启用。
3. 保存草稿、等待运行任务结束，通过应用菜单「退出」或托盘「退出」完整关闭 DSH，再重新打开。单独刷新可能仍使用旧插件清单并出现资源 404；窗口右上角关闭按钮也可能只是隐藏窗口。
4. 展开右侧栏，在「开始」页选择「侧边会话」。右栏收起时，可用官方右栏开关或 `Ctrl + Alt + B` 展开。

无需先手动下载或解压。这个地址指向单插件 Release 安装包，不是整个仓库。

### 方式二：先下载，再从本地文件安装

从 [Release](https://github.com/hechucaixuanzhi/my-dsh-plugins/releases/tag/session-panel-v2.4.0-dsh020rc2.9) 的 Assets 下载 `dsh-local-session-panel-2.4.0-dsh020rc2.9.tgz`，**无需解压**。例如自行保存到 `D:/DSH-plugins/downloads` 后，在同一个「包名或地址」框填写：

```text
file:D:/DSH-plugins/downloads/dsh-local-session-panel-2.4.0-dsh020rc2.9.tgz
```

路径须换成实际保存位置，包含完整文件名，不带引号。然后按方式一的安装、启用、完整退出和打开入口步骤操作。

### 方式三：从仓库里的单插件目录安装

下载并解压仓库后，定位到 `plugins/session-panel`，确认该目录直接包含 `package.json`、`cordis.patch.yml` 和 `lib`。例如仓库放在 `D:/DSH-plugins/my-dsh-plugins`，在「包名或地址」框填写：

```text
D:/DSH-plugins/my-dsh-plugins/plugins/session-panel
```

示例目录须实际存在，不能只照抄后粘贴。不要选仓库根目录或 `plugins` 父目录；本仓库根不是可安装 Bundle。使用本地目录安装时，请保留该目录，避免安装来源失效。

### 常见问题

- **“路径不存在或不是有效的插件包”**：确认本地绝对路径存在；目录应直接包含插件清单，而不是多包集合。路径格式可参考以上 Windows 示例。
- **GitHub 地址安装失败**：先用浏览器下载独立 `.tgz`，再采用方式二。切换 npm 镜像源不等于提供 GitHub 下载代理。
- **填写包名却找不到包**：当前未发布 npm 版本，`@dsh-local/session-panel` 只是包身份；请用以上独立安装包地址或本地路径。
- **填写仓库链接或 Source code 压缩包**：整个仓库、GitHub `tree/...` 网页和自动生成的 Source code 归档都不是本插件安装入口。请选择 Release 的独立 `.tgz` 或方式三的单插件目录。
- **安装后找不到入口或显示资源 404**：确认启用状态及 DSH 版本，保存草稿、等待任务结束后完整退出重开，再展开右栏。不需要删除会话或清空账号数据。

安装地址格式参考[官方插件管理说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/boot/plugin-manager/README.md)。下载及安装仍取决于本机网络、文件路径和 DSH 版本。

### 升级与卸载

升级请按当前官方插件管理流程停用/卸载旧包，再安装新版。不要删除会话日志、清空账号配置或禁用其他插件作为升级步骤。插件卸载不等于删除 DSH 保存的历史；如需删除历史，请使用官方数据管理流程并先备份。

本插件可独立安装，不需要修改 DSH 核心或另配模型密钥。使用 DSH 已配置的模型与权限，模型调用仍按提供方的规则计费。

## 使用示例

在主对话中打开侧边会话后，可以直接提问：

> 主任务现在进行到哪一步？请根据执行轨迹说明最近完成的工作，并区分已确认的信息和推测。
>
> 主对话提到的这个技术名词是什么意思？请结合当前任务，用新手能理解的方式解释。
>
> 请只读总结主对话最近一次工具调用的目的和结果；如果还没有返回结果，请明确说明。

每个主对话绑定独立的侧会话。切换主对话后，侧聊历史与草稿会随所属主对话切换。侧边 Agent 也可以独立执行获准任务；对主对话的观察接口保持只读。

## 数据与权限

- 历史由 DSH 会话持久化服务保存，不把聊天存到插件包或浏览器 localStorage。每个主对话通过稳定命名空间派生侧会话身份。
- 早期按主对话派生的深度 1 侧聊，可按官方继承前缀迁移到隐藏、独立的深度 0 根会话；旧日志保留。迁移遇到运行中的旧 Agent 或身份不合法会停止，不强制覆盖。
- 历史迁移仅覆盖按主对话派生的旧侧会话，不支持早期单例模式的历史迁移。
- 每次请求的主观察快照为近期 36 条消息、20 个步骤和 24 条事件摘要；工具摘要最多 1200 字符、步骤摘要最多 160 字符。旧记录可通过只读工具按需补查，每页最多 30 条，长事件每段最多 12000 字符。固定快照用于同一轮分页；检查后来新增的进度时应重新获取最新快照。
- 旧摘要接口的 240 条上限不删除持久化历史。模型上下文仍受官方窗口和压缩约束；未记录、已不可用的内容不能凭空恢复。
- 主任务运行时，潜在冲突工具有类别守卫，明确授权只覆盖当前侧任务，并在空闲时失效。工具名规则和提示词不是安全沙箱；未知工具与通用终端仍需要谨慎授权。
- 主记录会进入所选侧模型的上下文。插件没有额外遥测/独立云端服务，但不替模型提供方保证隐私。不要把凭据、私有日志或会话截图直接发到公开 Issue。

## 兼容性与已知限制

- 当前版本仅声明兼容 DSH Desktop `0.2.0-rc.2`。插件使用部分内部 Controller 接口，升级 DSH 前需确认兼容性。
- 插件专有提示语和界面标签目前以中文为主；中英文文档不代表界面已完全双语化。
- 离线回归和断线故障注入检查不等于所有原生网络中断、第三方工具或未来 DSH 版本均已验证。
- 初次安装后，建议先发送短消息，并切换两个主对话检查历史和草稿隔离；不要在重要任务运行时主动断网测试。

详细版本来源、人工验收和自动检查范围见[发布与验证说明](../../docs/release-checks/session-panel.md)。
